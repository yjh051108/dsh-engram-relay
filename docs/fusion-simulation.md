# 三维度索引准确率 + 融合仿真报告

> 按数学建模竞赛规格：问题重述 → 数据 → 方法 → 结果 → 结论 → 局限。

## 1. 问题重述

记忆唤醒的排序融合需要知道：**知识（语义）/ 因果 / 时序三个维度各自的索引准确率是多少？融合（τ 加权）比纯语义好多少？**

## 2. 数据（真实，零合成）

| 项 | 值 |
|---|---|
| 记忆 | 60 条真实记忆（`~/.dsh/engram-relay/engrams.jsonl`，含 causes/effects 因果边、reinforces 强化时间戳、hits、createdAt） |
| 查询 | 85 条 = 60 条记忆标题（自检索标定）+ **25 条真实用户消息**（会话 session-12ca2121 导出，fork 插件→适配→优化的真实提问） |
| 嵌入 | 真实 bge-small-zh（TS ONNX，包内模型，零 Python）512 维 |
| GT | 自身 + 因果直接邻居 + 共享主题关键词（粗标注，诚实声明） |

## 3. 方法

- **知识通道**：cos(q, m) 全排序 → Recall@k
- **因果通道**：语义 top-50 候选 → causes/effects 2 跳 BFS 传播 → 补盲增益 + 扩展精确率
- **时序通道**：recency / 强化次数 / hits / 幂律激活 A=ln(Σt⁻ᵈ)（d=0.5）→ 候选池内相关 vs 无关的条件 AUC
- **融合**：f 各自 z-score → s = τ_sem·f_sem + τ_cause·f_cause + τ_time·f_time → 网格扫 τ → top-3 注入 recall@3（仅 25 条真实用户查询）

## 4. 结果

### ① 知识通道（语义索引准确率）

| 指标 | 值 |
|---|---|
| Recall@1 | 20.1% |
| Recall@3 | 29.8% |
| Recall@5 | 35.2% |
| Recall@10 | 46.2% |

**语义排序质量有限**——top-3 只能召回约 3 成 GT，这是融合的空间。

### ② 因果通道

| 指标 | 值 |
|---|---|
| 语义 top-50 覆盖 GT | 1025/1073 (95.5%) |
| 因果 2 跳补盲 | **+34 条 GT**（语义漏掉、因果捞回） |
| 因果可达总 GT | 1059/1073 (98.7%) |
| 传播扩展精确率 | 6.6% |

**因果补盲真实存在**（+34 条，把语义漏掉的 4.5% GT 捞回 3.2pp），但**扩展精确率低（6.6%）**——因果的正确用法是"补盲召回"而非"排序特征"（融合网格里 τ_cause=0 验证：0/1 传播特征对排序是噪声）。

### ③ 时序通道（条件 AUC，候选池内相关 vs 无关）

| 特征 | AUC |
|---|---|
| recency（负=新） | 0.304（**反转**：更旧更相关） |
| 强化次数 | 0.398 |
| hits | 0.384 |
| 激活 A | 0.496（≈0.5 无判别力） |

**时序信号存在但方向是反的**：记忆库是"过去工作的总结"，新查询问的是过去的事 → 新记忆反而无关。**τ_time 的方向必须数据驱动**（允许负权重），不能预设"越新越优先"。

### ④ 融合

| 配置 | recall@3（25 条真实用户查询） |
|---|---|
| 基线（纯语义 τ_sem=1） | 76.9% |
| **最优（τ_sem=0.5, τ_cause=0, τ_time=0.5）** | **82.1%（+5.1pp）** |
| 语义+因果 | 76.9%（无增益） |
| 语义+时序 | 71.8%（τ_sem=1, τ_time=-1 组合） |

## 5. 结论

1. **三个维度的准确率是"接力"不是"并列"**：语义做排序（Recall@3 29.8%）、因果做补盲（+34 GT）、时序做调制（方向需学习）——直接加权融合的增益有限（+5.1pp）且小样本置信度低。
2. **融合权重必须数据驱动**：时序方向反转证明了"按经验标定 + 在线更新 τ"的必要性（PID 式增益调度）。
3. **因果传播做排序特征是负资产**（精确率 6.6%）：应保持"候选池扩展"角色，注入排序仍以语义为主。

## 6. 局限（诚实声明）

- **样本小**：25 条真实查询、13 条有 GT——+5.1pp ≈ 1 条查询的差异，**置信度低**，需更大查询集复验；
- **GT 粗**：主题关键词标注（沿用 simulate_real.py 的诚实声明），无法区分同主题内的精确性；
- **自检索查询偏乐观**：维度标定用（Recall@k），注入指标只用真实用户查询；
- **时序特征未分场景**：recency 反转可能只在"总结型记忆库"成立，不同使用模式需要在线自适应。

```sh
node --experimental-strip-types tests/simulate-fusion.mjs
```
